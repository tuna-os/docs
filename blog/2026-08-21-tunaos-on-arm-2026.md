TunaOS is a bootable-container desktop: the OS is a container image, updates
are atomic, rollbacks are one command, and every artifact is signed and
verifiable. That model is hardware-agnostic — so which laptops can you
actually run it on today? Here's the 2026 state of TunaOS on ARM, and how
the ARM story compares to the mature x86_64 catalog.

<!-- truncate -->

## The short version

| Path | Hardware | Status | How you install |
|---|---|---|---|
| **Apple Silicon** | M1/M2 Macs | Installer tooling + verified catalog; macOS app milestone remaining | macOS app → recoveryOS handoff → bootc install (`bootc-installer-asahi`) |
| **Snapdragon X Elite** | Lenovo ThinkPad X13s (SC8280XP) | Live ISO, auto-rebuilt on every push; `dakota-x13s` alpha | USB live ISO, or one-command `bootc switch` from another bootc OS |
| **x86_64** | Anything modern (Intel/AMD) | Full production catalog | USB live ISO / bootc switch — 14+ variants |

## Apple Silicon: the most common ARM Linux machines

Apple Silicon Macs are, by some measures, the most common ARM Linux machines
in the world — and TunaOS now has a first-class path for them via
[bootc-installer-asahi](https://github.com/tuna-os/bootc-installer-asahi).
The macOS app splits your disk, hands off to recoveryOS, and a minimal
bootstrap payload runs `fisherman` on first boot to `bootc install` the
image you picked. LUKS fail-closed and Wi-Fi handoff are wired into the
first-boot flow.

The catalog is a verified allowlist: only images that pass the
golden-manifest harness (36/36 checks each) are offered — today **bonito**
and **grouper**. The payload layout is modeled on fedora-asahi and
nixos-asahi so the approach stays upstream-compatible, and the tooling
explicitly supports packaging Dakota, Bluefin, and Bazzite images too.

**Today's boundary:** M1/M2 only. M3+ support follows Asahi upstream's
installer roadmap, and the macOS app (D3) is the remaining milestone before
the path is fully click-through.

## Snapdragon X Elite: the Windows-ARM laptop that became a Linux box

The Lenovo ThinkPad X13s (Qualcomm SC8280XP) is the reference device for
Linux on Windows-on-ARM laptops, and TunaOS ships two images built for it:

| Variant | Base | Status |
|---|---|---|
| **bonito-x13s** | Bonito (Fedora Atomic GNOME) | Live ISO, rebuilt automatically on push |
| **dakota-x13s** | Project Bluefin Dakota | Alpha — tracks upstream |

Both ship the full X13s support stack out of the box: the jlinton/x13s
kernel enablement, Qualcomm firmware, Bluetooth, power management
(`pd-mapper`), battery monitor firmware, and the required kernel arguments —
all preconfigured. If you're already running any bootc-based OS on the
X13s, switching is one command:

```bash
sudo bootc switch ghcr.io/tuna-os/bonito-x13s:latest
sudo reboot
```

Updates stay atomic from then on: `sudo bootc upgrade`, rollback on
failure, verified by the same container-native pipeline as every TunaOS
image.

## x86_64: the production catalog

On Intel/AMD hardware the full catalog applies — Yellowfin GNOME, Albacore
GNOME, Skipjack KDE (CentOS Stream 10), Tromsø KDE, **Gurnard** (Ubuntu
24.04 LTS + Pantheon), COSMIC, XFCE Linux, Bonito (Fedora), Niri, Marlin
(Arch), Guppy (Gentoo), Flounder (Debian), and more. If you want the most
supported, most boring, most enterprise-ready TunaOS, x86_64 is where the
largest fleet runs.

## Which one should you pick?

- **Own a Mac?** Try Apple Silicon — it's the most exciting ARM path, and
  the hardware-testing call in the Asahi repo is the fastest way to get
  involved (two documented CI tiers: a funded Scaleway rental, or a
  volunteer's M1 Air).
- **Own an X13s or another Snapdragon X Elite laptop?** Grab the
  `bonito-x13s` live ISO — it's rebuilt on every push, so what you download
  is the latest verified boot image.
- **Just want TunaOS today?** x86_64, any variant, 20 minutes, done.

All three paths share the same guarantee: whatever you run, it's a bootc
image — atomic, rollback-able, cosign-verified, and updated on the upstream
schedule rather than whenever a maintainer gets around to it.
