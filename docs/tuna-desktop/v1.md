Authority: the v1 definition spec (`20261009134949-7190f8bf-tuna-desktop-v1-definition`),
as amended by [ADR 0008](https://github.com/tuna-os/tuna-desktop/blob/main/docs/adr/0008-v1-beta-track-and-release-scope.md).
This page mirrors its checklist; where they disagree, the spec and ADR win.

## The bar

v1 means a desktop you can switch to without losing anything GNOME 51
does, and that feels faster while doing it: every tracked capability
verified working, no known gaps left open, and responsiveness
measurably quicker than GNOME on the same machine while using no more
CPU. Baseline is GNOME 51 as shipped in the Marlin GNOME image, on
identical hardware and the same image family.

Performance means: beat GNOME on responsiveness (overview opens,
input reaction, animations) and match it on CPU and memory. GPU-aware
cost accounting and total-power comparison were waived for v1 by the
owner on 2026-10-13 and remain a follow-up.

## What the session still takes from GNOME

"No GNOME fallback" below means the user session's shell and compositor
are Tuna's own. The session is not independent of GNOME
([#1051](https://github.com/tuna-os/tuna-desktop/issues/1051)):

- It runs GNOME's daemons: `tuna-session` starts gnome-settings-daemon's
  plugins through gnome-session's `gnome-session.target` and holds
  gnome-session's leader FIFO
  ([session operations](https://github.com/tuna-os/tuna-desktop/blob/main/docs/session-operations.md)); both are package
  dependencies (`packaging/arch/PKGBUILD`). Apps use
  xdg-desktop-portal-gnome for screenshots and screen sharing.
- It serves GNOME-private D-Bus interfaces (`org.gnome.Mutter.*` and
  `org.gnome.Shell.*`, listed in
  [protocols.md](https://github.com/tuna-os/tuna-desktop/blob/main/docs/protocols.md#gnome-d-bus-interfaces)) to those daemons
  and the portal backend. GNOME makes no compatibility promise for them,
  so any GNOME release can change what Tuna has to serve. Each GNOME
  release is therefore re-baselined before a Tuna release claims parity
  with it ([release runbook](https://github.com/tuna-os/tuna-desktop/blob/main/docs/release.md#re-baselining-on-a-new-gnome-release)).
- The Marlin flavor is built on `ghcr.io/tuna-os/marlin:gnome`
  (`packaging/marlin/Containerfile`), which ships GNOME Shell.
- Login is GDM's. Until the greeter item below is met (epic
  [#1164](https://github.com/tuna-os/tuna-desktop/issues/1164)), the login
  screen is GDM's own greeter, which is GNOME Shell.

## Victory checklist

- [ ] Every tracked capability verifies as passing (parity checklist
  all green, each with its proof linked).
- [ ] No known gaps remain open (open gap list empty; latest audit
  finds nothing untracked).
- [ ] Daily work needs no GNOME fallback (launch, switch, notify,
  configure, lock — entirely in Tuna). This covers the user session; it
  still runs on the GNOME daemons and private interfaces listed above.
- [ ] Responsiveness beats GNOME 51 on identical hardware
  (published benchmarks).
- [ ] Resource use matches GNOME 51 (CPU, memory).
- Waived for v1, follow-up: power comparison, and methodology that
  records CPU and GPU cost separately with total power on every run.
- [ ] Shipped Marlin image flavor qualifies end to end (install,
  boot, real-greeter login, passing qualification run).
- [ ] Release safety nets hold (recovery without data loss, proven
  upgrade path).
- [ ] Every TunaOS variant ships a qualified Tuna flavor (install,
  real-greeter login, session, portals, lock/unlock per image digest),
  or is published as unsupported with a recorded reason (ADR 0008).
  Current inventory, immutable subjects and gate limits:
  [variant qualification matrix](https://github.com/tuna-os/tuna-desktop/blob/main/docs/v1-variant-qualification.md).
- [ ] The login screen is Tuna Desktop's own greeter on GDM's daemon,
  matching GDM 51's login screen (user list, password, fingerprint,
  smartcard and multi-step auth, accessibility and input sources
  before login, user switching, GDM policy keys) on every variant,
  with no GNOME Shell greeter left
  ([ADR 0008](https://github.com/tuna-os/tuna-desktop/blob/main/docs/adr/0008-v1-beta-track-and-release-scope.md) item 6,
  epic [#1164](https://github.com/tuna-os/tuna-desktop/issues/1164)).
- [ ] This list stays public and current — one click from the front
  page, readable without asking anyone.

## Status, 2026-11-20

No item above is ticked, and the owner has not declared v1 met (epic
[#577](https://github.com/tuna-os/tuna-desktop/issues/577)). Recorded
evidence per item, against main `e0001376b` unless a run names another
subject:

- **Capabilities:** the [parity ledger](https://github.com/tuna-os/tuna-desktop/blob/main/docs/parity-ledger.md) has 77 rows:
  15 `pass`, 8 `pass (nested)`, 51 `partial`, 3 `missing`.
- **Responsiveness:** the paired GNOME 51 run
  [44598171676](https://github.com/tuna-os/tuna-desktop/actions/runs/44598171676)
  on main `8a93bd8cb` passes every enforced budget
  ([#503 comment](https://github.com/tuna-os/tuna-desktop/issues/503#issuecomment-7028378405)).
  Overview response p95 is 161 ms against GNOME's 376 ms (the gate marks
  that decision unstable: 90% interval 0.36–1.14) and p50 158 against
  161 ms; frame-interval p99 is 13.3 against 26.7 ms. #503 stays open.
- **CPU:** in the same run every CPU ratio is at or below GNOME's except
  overview desktop CPU, 1.05× GNOME (90% interval 0.85–1.15). Idle total
  CPU mean, 0.24 against 0.17, misses its target although its budget
  passes.
- **Memory:** replaying that run through the PSS gate that
  [#1075](https://github.com/tuna-os/tuna-desktop/pull/1075) added gives
  0.76–0.84× GNOME on all four PSS metrics (desktop at idle: 207 against
  269 MiB; [#503 comment](https://github.com/tuna-os/tuna-desktop/issues/503#issuecomment-7028511849)).
  The gate reports memory but does not enforce it yet.
- **Endurance:** the 24-hour soak passed on v1.0.0-beta.3 (published
  `marlin:tuna`, source `721c5503`): 86 400 s, session PSS 452.7 →
  464.4 MiB (+0.39 MiB/h after warmup), native client frame-interval p99
  13.34 ms ([#203 comment](https://github.com/tuna-os/tuna-desktop/issues/203#issuecomment-6995888909)).
- **Marlin flavor and variants:** on their current `:tuna` digests
  (v1.0.0-beta.3 packages), 14 of the 15 required variants, Marlin
  included, pass all 13 core gates of the GDM qualification journey;
  sailfin passes 12 of 13: logout hangs on a stray IBus daemon
  ([#1014](https://github.com/tuna-os/tuna-desktop/issues/1014); fix
  [#1235](https://github.com/tuna-os/tuna-desktop/pull/1235) is open and
  needs a release). Details in the
  [variant matrix](https://github.com/tuna-os/tuna-desktop/blob/main/docs/v1-variant-qualification.md#beta3-qualification-on-current-tuna-digests-2026-11-16-to-2026-11-19)
  and on [#1050](https://github.com/tuna-os/tuna-desktop/issues/1050#issuecomment-7003191134).
- **Release safety nets:** the [upgrade, rollback and crash-recovery
  proof](https://github.com/tuna-os/tuna-desktop/blob/main/docs/upgrade-recovery.md) has no release pair yet: its target image
  is the next beta, v1.0.0-beta.4, which is not cut.
- **Security:** ADR [0010](https://github.com/tuna-os/tuna-desktop/blob/main/docs/adr/0010-same-uid-trusted-identity.md) and
  [0011](https://github.com/tuna-os/tuna-desktop/blob/main/docs/adr/0011-lock-auth-and-capture-grant-lifecycle.md) are proposed
  and await the owner's decision; their remaining gaps are in open
  [#1169](https://github.com/tuna-os/tuna-desktop/pull/1169).
- **Login screen:** the Tuna greeter stack
  ([#1176](https://github.com/tuna-os/tuna-desktop/pull/1176)) is open;
  every variant still logs in through GDM's own greeter.

## Where the evidence lives

- Capability tracking: `docs/parity-ledger.md`. The nightly
  `victory-checks` signal counts every ledger row by status; only
  `pass` counts toward the pass fraction, `pass (nested)` rows count
  toward the total until they pass outside the nested session.
- Gap issues: `[GNOME 51 gap]` label on GitHub.
- Benchmarks: the published performance lanes and nightly gate.
- Image qualification: Marlin flavor lanes and the published-flavor
  nightly.
- Upgrade, rollback and crash recovery on the published image:
  `docs/upgrade-recovery.md`.
- Program order and gates: `docs/roadmap.md`.

## Betas before v1

`v1.0.0-beta.N` prereleases ship from `main` while this list is still
open ([ADR 0008](https://github.com/tuna-os/tuna-desktop/blob/main/docs/adr/0008-v1-beta-track-and-release-scope.md),
[release runbook](https://github.com/tuna-os/tuna-desktop/blob/main/docs/release.md#prereleases-betas-and-release-candidates)).
Every beta lists its open rows as known limitations and claims no item
above.

## Non-goals

Extension broker and public API stay post-1.0 unless explicitly
promoted; nothing in v1 depends on them.
